# 20 路 25fps 性能优化 v2 Implementation Plan

> 取代 2026-08-08 版（P1/P2/P3 已完成、P4 实验回退）。本版基于 08-17 ImageData 设备化改造后的架构。

**目标**：20 路（enable_preview=false）每路 ≥25fps（总吞吐 ≥500fps），VRAM < 14GB，系统内存 < 4GB；
预览路支持 GPU 就地绘制 + 设备 NV12 编码。

**硬件**：RTX 4060 Ti 16GB / i7-12700 / 32GB。模型：yolo11n_nms_b8.engine（动态 1-8）。
**测试**：本地文件 20 路（test_data/bench_videos/cam00-19.mp4）。

## 现状数据流（20 路瓶颈）

```
CUVID → D2H 3.1MB → host NV12 memcpy → BatchRequest(host ptr)
  → process_batch: H2D 3.1MB + nv12→BGR kernel + D2H 6.2MB → host BGR
  → batch_predict: yolo_preprocess_batch_cuda H2D 6.2MB + kernel → TRT
  → [预览] CPU vis_det 绘制 → sws_scale BGR→NV12 → NVENC/x264
```
- 每帧 ≈18.6MB PCIe + 每路独立 TRT context（20×）+ 每帧 cudaMalloc（直通路径）+ 20×200µs 轮询。
- 实测（08-10）：20 路 9.3fps/路，VRAM 13.3GB，进程 14.4GB RAM（swap）。

## 目标数据流（全 GPU，零 PCIe 推理）

```
CUVID(device NV12)
  → decode: D2D → FramePool 设备块（3.1MB，池化）        [0 PCIe]
  → BatchRequest{y_dev, uv_dev, owner}
  → yolo_preprocess_nv12_batch_cuda（新 kernel，设备内）  [0 PCIe]
  → TRT batch_predict（设备 tensor 直连）                 [0 PCIe]
  → postprocess → host 结果（KB 级）
  → [预览] draw_*_nv12 设备就地绘制                        [0 PCIe]
  → [预览] D2H 3.1MB → enc_frame → NVENC/x264
```
每路不再加载 TRT 引擎（batch-only 模式），仅 BatchScheduler 持 1 个 prototype。

## 任务

### T1: SDK — NV12 批量预处理 kernel（设备零拷贝）

- `csrc/vision/processors/cuda/yolo_preproc.cu/.cuh`：
  - `kernel_nv12_fusion_batch`：3D grid（z=batch），每图参数 {y_ptr, uv_ptr, w, h, step_y, step_uv, scale, pad_w, pad_h} 打包单块 H2D；BT.601 YUV→RGB（与单帧 kernel_nv12_fusion 一致）；最近邻 + letterbox + /255。
  - `yolo_preprocess_nv12_batch_cuda(images, out, dst_size, pad, records, stream, dst_pool)`：
    - 逐图判定 plane(0) 是否设备指针（cudaPointerGetAttributes）：设备→直接用；host→上传 ws 缓冲（逐图 memcpyAsync）后取设备槽指针。
    - 输出 [batch,3,h,w] FP32 GPU（CudaOutputBufferPool 复用）。
- `cuda_processor_backend.cpp::yolo_preprocess_batch`：全部图 type==NV12 且 plane_count>=2 → NV12 batch kernel；否则原 BGR 路径。
- `cpu_processor_backend.cpp::yolo_preprocess_batch`：含 NV12 图 → 逐图 cvtColor 到临时 BGR 再走原 batch（CPU 正确性回退）。
- 测试 `tests/test_nv12_batch_preproc.cpp` [gpu]：host NV12 与设备 NV12 各 2 帧，batch 输出 vs 逐帧 yolo_preprocess_nv12_cuda 输出 allclose。

### T2: 解码设备直通 + 显存池

- `StreamDecoder`：`set_device_only(bool)` —— true 时跳过 av_hwframe_transfer_data（省 D2H），y_plane/uv_plane 置空，仅暴露 device 指针。
- `FramePool` 改为 PipelineManager 共享成员，注入 Pipeline；decode_loop 的 D2D 目标从每帧 cudaMalloc（alloc_device_buffer）改为池块（shared_ptr + 池 deleter）。非批 GPU 直通路径同样受益。
- 批 GPU 直通门槛：`batch_scheduler_ 已启动 && 全部模型 detection+gpu 无 ROI`。

### T3: BatchScheduler 设备化

- `BatchRequest`：+ `y_device/uv_device/y_step_device/uv_step_device`、`std::shared_ptr<uint8_t> gpu_nv12`（owner，池块生命周期）。
- `BatchResult`：+ `std::mutex/cv`（替代 200µs 轮询）、`std::shared_ptr<uint8_t> nv12_gpu` + w/h（预览已绘制设备帧）。
- `process_batch`：
  - 设备请求 → `ImageData::from_planes({y_dev, uv_dev}, 2, NV12, w, h, Device::GPU, owner)` 视图；host 请求 → 现有紧凑化 + host NV12 视图（混合批按图分流，kernel 逐图判定）。
  - 统一走 `det->batch_predict`（T1 后自动设备 NV12 预处理）。
  - 预览（need_bgr）设备帧：推理后经 CudaProcessorBackend `draw_rect_nv12/draw_text_nv12` 就地绘制，`res->nv12_gpu = req.gpu_nv12`。
  - 逐结果 `cv.notify_one`；stop 时排空 pending 全部 notify。
- scheduler_loop 首轮前 warmup（合成 NV12 批跑一次 prototype，暖 TRT/预检池）。

### T4: Pipeline 设备链路 + 设备 NV12 编码

- `PendingFrame` 复用 gpu_nv12；process_loop：设备请求填 device 字段；CV 等 future；
  - 预览：`ef.gpu_nv12 = res->nv12_gpu`（w/h/pts），不再要 BGR；快照 latest_bgr_ = 设备 NV12 视图（owner 池块）。
  - 非预览：无 BGR、无快照（HTTP 快照仅预览路可用）。
- `Pipeline::encode_jpeg`：支持 NV12 设备快照（toCpu → cvt_color CVT_NV122PKG_BGR → asMat）。
- `EncodedFrame`：+ `std::shared_ptr<uint8_t> gpu_nv12`。
- `StreamEncoder::encode_from_gpu_nv12(d_nv12, w, h)`：cudaMemcpy2D D2H 到 enc_frame 平面（兼容 linesize）→ send/receive；限速逻辑复用。
- encode_loop 优先级：gpu_nv12 → gpu_bgr（旧）→ bgr_image。
- NVENC 会话失败（auto 模式）→ 回退 libx264（PRD 要求，GeForce 8 会话上限）。

### T5: batch-only 模式（省 20×TRT context）

- `InferGroup`：`batch_only=true` 时不建引擎、不 warmup、`gpu_nv12_ready_` 按 cfg 计算；`run_models` 被调用则记错返回 0；add/remove/update_model 返回 false。
- Pipeline 构造时判定（门槛同 T2）并传入 InferGroup。
- BatchScheduler 注册模型时已加载 prototype（唯一 TRT context）。

### T6: 构建 + 端到端验证 + 基准

- cmake 增加 `-DBUILD_SURVEILLANCE=ON -DBUILD_SURVEILLANCE_TESTS=ON`（现 OFF）。
- 全量 SDK 测试回归（BUILD_TESTS）+ surveillance_test。
- 种子 `build/bin/data/models.json`（det=yolo11n_nms_b8）+ `tasks.json`（20 任务，enable_preview=false）。
- 运行 surveillance，采样 `/api/v1/metrics` + nvidia-smi + 进程内存：
  - 目标：20 路 × ≥25fps（总 ≥500fps）、VRAM < 14GB、进程 RAM < 4GB、无 swap。
- 预览冒烟：3 路 enable_preview=true（NVENC/x264 输出 mp4），验证有框、帧数正确。
- 数据写入 `docs/benchmark_20stream.md`。

## 约束

- GPU kernel `#ifdef WITH_GPU`；所有优化不破坏 CPU/TPU 回退（host 批路径原样保留）。
- 无异常代码库：错误走返回值 + MD_LOG_ERROR。
- 不提交（用户未要求）；工作区 capi/csharp/rust 未提交改动保持原样。
- 验证命令：
  - `cmake --build build --parallel`（vcvars64 + Ninja）
  - `cd build && ctest -C Release --output-on-failure`
